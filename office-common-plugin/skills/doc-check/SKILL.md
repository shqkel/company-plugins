# 문서 점검

**고치지 않는다. 무엇이 걸리는지만 짚는다.**
작성한 사람과 점검하는 사람이 같으면 자기 글의 빈자리는 보이지 않는다. 이 스킬은 그 두 번째 눈이다.

## 입력값

| 항목 | 필수 | 기본값 |
|------|------|--------|
| 점검할 문서 | 필수 | — |
| 문서 종류 | 선택 | 문서에서 판단 (보고서·공문·게시물·안내문) |
| 추가 점검 항목 | 선택 | 없음 |

## 점검 항목

| 구분 | 무엇을 보는가 |
|------|---------------|
| **빈자리** | `TBD`·`미정`·`OOO`·`[  ]`처럼 채우다 만 자리 |
| **숫자** | 표의 합계가 항목의 합과 맞는가, 본문 숫자와 표의 숫자가 같은가, 단위(원·천원·백만원)가 섞이지 않았는가 |
| **날짜** | 표기 형식이 문서 안에서 통일됐는가, 요일이 실제 날짜와 맞는가, 기한이 이미 지난 날짜인가 |
| **빠진 항목** | 그 종류의 문서가 갖춰야 할 자리(제목·기간·담당·근거·연락처)가 있는가 |
| **이름·직함** | 같은 사람·부서·사업이 문서 안에서 다르게 불리는가 |
| **위험한 표현** | 확정되지 않은 것을 확정으로 쓴 문장, 외부에 나가면 안 되는 내부 정보, 단정적 약속 |

## 출력 구조

```markdown
# 점검 결과 — [문서 이름]

| 구분 | 판정 | 건수 |
|------|------|------|
| 빈자리 | 통과 / 지적 | N |
| 숫자 | | |
| 날짜 | | |
| 빠진 항목 | | |
| 이름·직함 | | |
| 위험한 표현 | | |

## 지적 사항

### 1. [구분] — [무엇이 걸리는가]
> [문서에서 그대로 인용한 대목]

[왜 걸리는지 · 무엇을 확인해야 하는지]
```

## 지키는 것

- **파일을 수정하지 않는다.** 고치는 것은 작성자의 몫이다. 고쳐 달라는 요청을 함께 받았더라도 점검 결과를 먼저 보여 주고 확인을 받는다.
- **인용 없이 지적하지 않는다.** 모든 지적에는 문서에서 그대로 가져온 대목을 붙인다.
- **추측으로 판정하지 않는다.** 문서 밖의 사실을 알아야 판단되는 것은 「지적」이 아니라 **「확인 필요」**로 따로 모은다.
- 걸리는 것이 없으면 없다고 말한다. 억지로 찾아내지 않는다.
