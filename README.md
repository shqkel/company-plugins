# company-plugins

우리 회사에서 쓰는 스킬을 **GitHub 저장소 하나에 모아 두고 부서끼리 나눠 쓰는** 템플릿이다.
git 설치도 터미널도 필요하지 않다. 저장소를 만드는 것도, 고친 스킬을 갈아 끼우는 것도 브라우저에서 파일을 끌어다 놓는 것으로 끝난다.

바로 쓸 수 있는 플러그인 하나(`office-common-plugin`)와, 새 플러그인을 만들 때 복사하는 뼈대(`_template`)가 들어 있다.

## 무엇이 들어 있나

| 스킬 | 하는 일 | 부르는 말 |
|------|---------|-----------|
| `meeting-minutes` | 회의 메모·녹취를 **결정사항 · 할 일 · 보류**로 가른다 | "회의록 정리해줘" |
| `weekly-report` | 한 주치 기록을 **주간업무보고 한 장**으로 만든다 | "주간보고 써줘" |
| `doc-check` | 내보내기 전 문서를 훑어 **빠진 항목 · 어긋난 숫자 · 위험한 표현**을 짚는다 | "보내기 전에 확인해줘" |

세 가지 모두 부서를 가리지 않고 매주 반복되는 일이다. 회의는 어디서나 하고, 보고는 매주 올라가고, 문서는 나가기 전에 누군가 봐야 한다.

`doc-check`는 **문서를 고치지 않는다.** 작성과 점검을 한 사람이 한 번에 하면 자기 글의 빈자리가 보이지 않으므로, 짚는 일만 따로 떼어 두었다.

## 폴더 구조

```
company-plugins/                   ← 저장소 최상위 = 마켓플레이스
├── .claude-plugin/
│   └── marketplace.json           # 카탈로그 — 이 파일이 있어야 남이 설치할 수 있다
├── office-common-plugin/                 # 플러그인 하나 (설치 단위)
│   ├── .claude-plugin/
│   │   └── plugin.json
│   └── skills/
│       ├── meeting-minutes/SKILL.md
│       ├── weekly-report/SKILL.md
│       └── doc-check/SKILL.md
└── _template/                     # 새 플러그인을 만들 때 복사하는 뼈대
    ├── .claude-plugin/plugin.json
    └── skills/_skill-template/SKILL.md
```

세 층이 겹쳐 있다 — **마켓플레이스**(저장소 전체) 안에 **플러그인**이 들어가고, 플러그인 안에 **스킬**이 들어간다.
설치는 플러그인 단위로 하고, 실행은 스킬 단위로 한다. `office-common-plugin`을 한 번 설치하면 스킬 셋이 함께 들어온다.

`_template`은 `marketplace.json`에 등록돼 있지 않아 설치 목록에 뜨지 않는다. 복사해 이름을 바꾸고 등록하는 순간부터 뜬다.

## 1. GitHub 저장소 만들기 (처음 한 번)

> [!IMPORTANT]
> **점(`.`)으로 시작하는 폴더는 끌어다 놓아도 올라가지 않는다.** GitHub 업로더가 걸러낸다.
> 이 저장소에서 그런 폴더는 `.claude-plugin` 셋이고, 그 안의 파일은 **웹에서 직접 만든다**(③).
> 숨김 표시를 켜도 결과는 같으므로 드래그로 해결하려 하지 않는다.

**① 저장소를 만든다**

<https://github.com/new> 에서 Repository name에 `company-plugins`를 넣고 **Public**을 고른 뒤 **Create repository**.
비공개(Private)로 만들면 Cowork가 저장소를 읽지 못할 수 있다.

**② 끌어다 놓을 수 있는 것부터 올린다**

**Add file → Upload files** → `office-common-plugin` 폴더를 통째로 끌어다 놓고 **Commit changes**.
`skills/` 아래 `SKILL.md` 셋만 올라가고 점 폴더는 빠진다. 실수가 아니라 위에 적은 그 성질이다.

**③ 점 폴더에 든 파일을 웹에서 만든다**

**Add file → Create new file**을 열고 **이름 칸에 경로를 그대로 입력**한다. `/`를 치는 순간 폴더가 함께 생긴다.

| 이름 칸에 입력할 경로 | 붙여 넣을 내용 |
|----------------------|----------------|
| `.claude-plugin/marketplace.json` | 내 컴퓨터의 같은 파일 |
| `office-common-plugin/.claude-plugin/plugin.json` | 내 컴퓨터의 같은 파일 |

내용을 붙여 넣고 각각 **Commit changes**.

> [!WARNING]
> **경로에 공백을 넣지 않는다.** `/` 뒤에 스페이스가 한 번 눌리면 GitHub는 이름이 ` .claude-plugin`인 **다른 폴더**를 만든다.
> 눈으로는 거의 구분되지 않지만 Cowork는 `Marketplace sync failed`로 멈춘다.

**④ 저장소 최상위에 `.claude-plugin` 폴더가 보이면 끝났다**

한 번 올라간 뒤에는 점 폴더도 여느 폴더와 같다. 안의 파일을 고칠 때는 GitHub에서 그 파일을 열고 **연필 아이콘**으로 고친다.

## 2. Cowork에 등록하기

**① 설정 → 플러그인 → [추가] → 마켓플레이스 추가**

**② URL 칸에 `본인ID/company-plugins` 입력** — 아래에 뜨는 «"본인ID/company-plugins" 사용»을 클릭해야 주소가 확정된다

**③ [동기화]** — **자동으로 동기화**를 켜 두면 저장소가 바뀔 때 설치본도 따라 갱신된다

**④ 찾아보기 → 왼쪽 플러그인 → 위쪽 개인 탭 → `office-common-plugin` 카드의 [+]**

동료가 설치할 때도 같은 4단계다. 주소 한 줄(`본인ID/company-plugins`)만 알려주면 된다.

> [!IMPORTANT]
> 저장소를 등록한다는 것은 **그 저장소가 담은 지시문을 Claude가 읽고 따르게 한다**는 뜻이다.
> 남의 저장소를 등록할 때는 누가 만든 것인지 확인한다.

## 3. 스킬 실행하기

대화창에 `/`를 입력하면 설치된 스킬 목록이 뜬다. 고르고 요청을 붙인다.

```
/meeting-minutes 오늘 팀 회의 메모야. 결정된 것만 뽑아줘.
/weekly-report 이번 주 업무일지 폴더 읽고 팀장 보고용으로 정리해줘.
/doc-check 방금 만든 보고서 내보내기 전에 봐줘.
```

파일을 함께 올리거나 폴더를 가리키면 그 내용을 읽는다.

## 4. 고친 스킬 갈아 끼우기

**같은 경로에 같은 이름으로 올리면 덮어쓰인다.** 이 한 가지가 드래그 앤 드롭 버전 관리의 전부다.

1. 내 컴퓨터에서 `SKILL.md`를 고친다
2. GitHub 저장소에서 `office-common-plugin/skills/meeting-minutes/` 폴더를 연다
3. **Add file → Upload files** → 고친 `SKILL.md`를 끌어다 놓는다
4. Commit 칸에 무엇을 바꿨는지 한 줄 적는다 (예: `회의록에 다음 회의 항목 추가`) → **Commit changes**

스킬이 여럿이면 **저장소 최상위에서** `office-common-plugin` 폴더를 통째로 끌어다 놓아도 된다. 안에 든 파일이 각자 같은 경로로 덮어쓰인다.

**업로드는 덮어쓰기만 한다.** 내 컴퓨터에서 지운 파일은 저장소에 그대로 남는다.
스킬 이름을 바꾸거나 파일을 없앨 때는 GitHub에서 그 파일을 열고 **휴지통 아이콘 → Commit changes**로 지운다.

**판본을 함께 올린다.** `plugin.json`의 `"version"`을 `1.0.0` → `1.1.0`처럼 올려 두면 동료가 무엇이 새 것인지 알 수 있다. 이 파일은 점 폴더 안에 있어 끌어다 놓을 수 없으므로, GitHub에서 파일을 열고 **연필 아이콘**으로 고친다.

**되돌리려면** 파일을 연 뒤 **History**에서 이전 시점을 열고, 그때 내용을 복사해 다시 올린다. 업로드 한 번이 기록 한 줄이므로 언제 무엇을 바꿨는지 저장소가 스스로 남긴다.

## 5. 동료가 최신본 받기

**자동으로 동기화**를 켜 두었으면 그대로 갱신된다. 꺼져 있으면 **설정 → 플러그인**에서 해당 마켓플레이스의 **[동기화]** 를 누른다. 목록이 그대로면 Cowork를 새로고침한다.

## 6. 스킬·플러그인 늘리기

| 하려는 일 | 만드는 것 | `marketplace.json` |
|-----------|-----------|--------------------|
| 공통 스킬 하나 더 | `office-common-plugin/skills/새-스킬-이름/SKILL.md` | 고치지 않는다 |
| 부서 전용 플러그인 신설 | `_template` 폴더를 복사해 이름 변경 후 채운다 | **항목을 추가한다** |

부서 플러그인 `team-hr`을 만드는 경우, 최상위 `.claude-plugin/marketplace.json`의 `plugins` 배열에

```json
    {
      "name": "team-hr",
      "source": "./team-hr",
      "description": "인사팀에서 반복되는 문서 업무 묶음"
    }
```

`marketplace.json`에 적지 않은 플러그인은 목록에 뜨지 않는다. 폴더만 올리고 이 파일을 잊는 것이 가장 흔한 실수다.

**어떻게 묶을지는 순서가 아니라 쓰는 사람으로 정한다.** 모든 부서가 쓰면 `office-common-plugin`에, 한 부서만 쓰면 그 부서 플러그인에 넣는다. 설치가 플러그인 단위이므로, 안 쓰는 스킬이 딸려 오지 않게 하는 것이 기준이다.

## 7. 올리기 전 확인

- [ ] 저장소 최상위에 `.claude-plugin/marketplace.json`이 보인다 (드래그로는 올라가지 않는다)
- [ ] 스킬 폴더 **바로 안에** `SKILL.md`가 있다 (한 겹 더 들어가 있으면 인식되지 않는다)
- [ ] `SKILL.md` 맨 위 `---` 사이에 `name`과 `description`이 있다
- [ ] `description`에 **언제 이 스킬이 불려야 하는지**가 실제 말투로 적혀 있다
- [ ] `marketplace.json`의 `source` 값이 실제 폴더 이름과 글자까지 같다 (앞뒤 공백 포함)
- [ ] `"여기에~"`로 남은 자리가 없다

## 문제가 생기면

| 증상 | 원인 | 조치 |
|------|------|------|
| 개인 탭이 비어 있다 | 주소를 입력만 하고 확정·동기화하지 않았다 | 뜨는 «… 사용»을 클릭해 확정한 뒤 [동기화], 그래도 비면 새로고침 |
| 저장소를 찾지 못한다 | 주소가 `owner/repo` 형식이 아니다 | `본인ID/company-plugins` 형식으로 다시 입력 |
| `Marketplace sync failed`가 뜬다 | `source`가 가리키는 폴더 안에 `.claude-plugin/plugin.json`이 없다 — 경로에 공백이 섞여 다른 폴더가 만들어진 경우가 많다 | 저장소에서 그 파일을 열고 **연필 아이콘** → 이름 칸의 공백을 지우고 Commit. 빈 폴더는 저절로 사라진다 |
| 카드가 뜨지 않는다 | `marketplace.json`이 최상위 `.claude-plugin/` 밖에 있다 | GitHub에서 파일 위치 확인, 아니면 Create new file로 경로째 다시 만든다 |
| 고쳤는데 예전대로 동작한다 | 동기화되지 않았다 | [동기화] 후 Cowork 새로고침 |
| 스킬이 `/` 목록에 없다 | 설치 직후 목록이 갱신되지 않았다 | Cowork 새로고침 후 `/`로 재확인 |
| 스킬이 엉뚱할 때 튀어나온다 | `description`의 부르는 말이 너무 넓다 | 그 스킬이 맡을 요청의 말투만 남기고 좁힌다 |

## 저장소 없이 한 개만 나눠줄 때

스킬 하나를 급히 전달할 때는 **스킬 폴더(`meeting-minutes/`)를 압축해 ZIP으로 건네고**, 받는 쪽이 **설정 → 스킬**에서 그대로 업로드한다. 압축한 폴더 바로 안에 `SKILL.md`가 있어야 한다.

저장소는 스킬이 여럿이 되고 고치는 일이 반복될 때부터 값을 한다. ZIP은 받은 사람마다 판본이 갈리지만, 저장소는 한 곳만 갈아 끼우면 모두가 같은 것을 쓴다.
